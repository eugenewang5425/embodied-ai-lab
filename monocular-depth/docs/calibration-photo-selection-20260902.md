# 焦点 293 照片筛选结果

推荐 **16 张平衡方案**：前次试拍 8 张 + 本次补拍 8 张。
全部为 3840×2160、焦点 293、逐帧锁焦记录有效，保留四角覆盖和倾斜视角。
原始 25 张未删除、未覆盖。筛选照片已导出为完整原图的副本，并带有可追溯的逐张 JSON。

16 张的最大单张 RMS 为 **1.221573 px**，通过项目原有整体 ≤0.8 px、单张 ≤1.5 px 门槛。
16 张也高于至少 12 张的数量下限；“数量足”不表示姿态条件必然充分。
角点凸包覆盖为 **70.98%**，原始为 71.54%，四角拍摄位置均保留。
候选估计的板倾角范围为 5.26°–31.61°，不是独立角度测量。
筛选后画面上部中间及右侧中部仍缺少角点；凸包面积高不代表均匀覆盖。

## 方法及验证边界

从 25 张开始，每轮枚举每一种“少留一张”的组合，重新计算标定，选择满足覆盖约束且 RMS 最小的一种。
依次比较至 15 张；这是确定性的贪心后退筛选，**没有穷举全部子集，不能声称全局最优**。

约束为：保留初始角点凸包至少 90%、保留已有四个角区、至少 4 张估计倾角 ≥15°，
法向量在两个方向的角度跨度均至少 15°（若输入本身不足则不要求超过其初始跨度）。
角度约束使用候选内参估计，故只能用作筛选代理指标。
没有放宽项目原有标定门槛，没有改照片或角点以降低误差，没有混入焦点 286 的数据。

17 张是该筛选路径上首次通过拟合门槛的最大张数；对 19/18/17/16/15 张做条件五折比较后，
选择 16 张作为折中，另保留 17 张的完整备选。

**0.782198 px 是筛选集内部的一致性检查，不是独立验收。**
因为照片先被筛选，且方案数量也参考了这些交叉验证数值，该结果含选择偏差。
另外进行了更严格的五折检查：每折只在训练部分内部重新筛选 16 张，
评估全部留出照片，不按留出残差剔除难图，得到 **1.151360 px**。
该检查减少了逐图筛选泄漏，但固定 16 张这一数量仍基于已有数据选择，不是新采集测试集。
留出照片的角点也参与自身位姿估计；它仍不是独立实物尺寸或测距验证。

因此：本次实现的是“筛出较一致、满足拟合门槛的一组数据”，
**并没有解决原始困难照片上的误差，也没有证明米制测距准确**。
未创建或修改默认 `calibration/camera.json`，未自动启动后续推理或点云流程。
后续使用候选参数仍需保持同一相机、4K 模式、焦点 293、裁剪/变焦设置，并做独立尺度验证。

## 复现

在 monocular-depth 项目目录运行，输出目录必须尚不存在：

```powershell
uv run --no-editable python scripts/select_calibration_views.py --candidate outputs/calibration-focus293-pair-20260902/combined-candidate.json --output calibration/selected/focus293_16_rerun --retain-count 16
uv run --no-editable depth-calibrate solve --images calibration/selected/focus293_16_rerun/images --output calibration/selected/focus293_16_rerun/recomputed-camera.json
```

不传 `--retain-count` 时，默认选择贪心路径上保留张数最多且拟合通过的一组，本次为 17 张。
