按残差剔除照片的结果只作为敏感性分析，没有用它声称独立验证通过。

## 观察与判断

- 图片中确实有打印板，而不是电子屏幕上的图案。上下颠倒持板不影响 ChArUco ID 对应。
- 视角有变化，五折焦距估计相对稳定，说明这组数据有价值，不是拍摄失败或必须丢弃。
- 误差最大的 view_011、view_014 对应较极端倾角（候选估计约 63°、60°）。
  棋格在这些视角下明显压缩，角点定位更困难；view_015 也有明显边缘不锐利现象。
- 内参辅助插值几乎不改变结果，不能把问题简单归咎于未使用候选内参进行角点检测。
- 同一张图的平面单应性残差与重投影残差接近，提示图像角点/板平面一致性值得检查。
  **这不能单独证明纸张弯曲、手抖或自动对焦是根因。**
- 自动对焦开启是需要控制的变量，但现有日志没有记录采集过程中焦点是否真的改变。

## 下一步建议

先保留这一组，不改阈值、不人为继续删图凑分数。建议另拍一组 12–15 张受控照片，用于定位问题：

1. 纸张四边贴平到不易弯曲的硬板，避免抓持时挤压板面；不用重新打印尺寸已确认的图案。
2. 将板放到计划使用的工作距离，调清楚并锁定对焦。保持摄像头、分辨率、变焦/裁剪不变。
   当前采集程序还不提供焦点锁定按钮，不能把启动采集等同于焦点已锁定。
3. 使用均匀照明，尽量避开强侧逆光；停稳后再按 S。
4. 使用约 15°–35° 的左右/上下倾角，避免接近侧拍；增加画面上部和四角覆盖。
5. 新照片放进新会话，不混入原数据直接重算。先检查新组误差，再评估两组内参是否一致；
   若锁焦后内参不同，不能强行把两组当成同一套相机设置。

## 文件与复现

- 初次候选：`calibration/camera-4k-candidate-20260902.json`（quality_pass=false）。
- 诊断：`outputs/calibration-audit-20260902/audit.json`。
- 三张高误差照片的棋盘局部：同目录的 `board_crop_view_011.png`、`board_crop_view_014.png`、`board_crop_view_015.png`。
- 脚本：`scripts/audit_calibration.py`，只读取原图，拒绝覆盖既有输出目录。

```powershell
uv run --no-editable python scripts/audit_calibration.py --images calibration/sessions/session_20260902_081720_630577 --candidate calibration/camera-4k-candidate-20260902.json --output outputs/calibration-audit-rerun --physical-size-confirmed
```

`--physical-size-confirmed` 仅在用户确已尺量后使用，不会自动推断实物尺寸。

方法参考：[OpenCV ChArUco 标定](https://docs.opencv.org/4.x/da/d13/tutorial_aruco_calibration.html)、
[OpenCV ChArUco 检测与内参辅助插值](https://docs.opencv.org/4.x/df/d4a/tutorial_charuco_detection.html)。
