# 第69课第五轮预登记：排队动作与执行端保护

2026-10-01，起始提交222168d。第四轮发现0.4秒排队延迟造成11次接触；保护请求发出后，旧动作还能把车推前约24cm。本轮不改地图、观测、跟踪、身体或6cm余量，不修定位偏差，不新增课号。

## 两个因素与四组

原同比例控制器保持冻结。四组为原参照、仅队列预测、仅执行端保护、两者结合。队列预测用当前执行速度，依次预测已排队意图、此次新意图，然后按原同比例规则减到零；同时检查现在发出停车请求的完整队列尾段。只能使用先验图和截至当前帧的观测。

执行端保护位于延迟队列之后：对即将执行动作及随后立即同比例停车的整个车身扫掠检查观测点；不安全时直接在执行端减速，清掉尚未执行的旧意图。它是一项新的本地保护能力，不能写成原远端停车请求突然没了延迟。

执行端还检查控制信息是否过期：连续两个10Hz周期没有新控制结果后就本地停车、清空旧意图，并锁住这一回合，以免迟到结果重新启动。这个保守实验以安全停住为目的，不自动恢复任务。每次正常帧更新本地传感器；失联帧也继续感知和执行。

## 规划超时的因果模型

单列规划无输出试验：从5.0秒开始，连续10帧不给执行端新的控制结果（1秒），车辆继续运动。对照仍消耗先前队列，队列耗尽后维持上一执行速度；保护组在消息年龄达到0.2秒时本地减速。迟到结果丢弃，不能暂停车辆等规划算完。时间取上一轮固定选例首次保护请求5.6秒之前的整秒，不按新种子调选。

这是一项固定故障持续时间的离散调度试验，不是以本机每次规划墙钟耗时充当随机自变量，也不是实测多进程10Hz实时系统。普通闭环仍记录真实规划耗时，但没有把它叠加成实际运动延迟；不能宣称已解决原9秒规划计算。可复用的消息过期接口是独立执行端原型，真实线程/进程隔离与规划取消留待下一项。

## 批次、开发与冻结

开发仅窄路普通箱体种子0，延迟0.4秒的四组及1秒无输出的四组；可修接口错误，不能据此调控制或余量。正式冻结后：

- 桥接：第四轮窄路普通箱体种子8，零延迟、0.2、0.4秒三个旧参照，既有数组逐一复现（计时除外）。
- 主批：窄路×普通箱体/低路障/悬空杆×新种子11/12/13×0/0.2/0.4秒延迟×四组，共108回合。
- 环境参照：开阔、街区×普通箱体×种子11×0.4秒×四组，共8回合。
- 负例：0.50m窄口×普通箱体×种子11×0.4秒×四组，共4回合。身体能放下但外扩包络放不下，应原地拒绝。
- 规划无输出：窄路普通箱体×种子11/12/13×0.4秒×四组，共12回合。即使早于5秒结束也保留并注明未遇到故障。

合计135回合，不重复计数桥接。11/12/13不参与开发，不在正式结果后重新选种子或改变机制。每回合独立驾驶，位置精确为受控条件。

## 正式冻结前记录

六项已知答案测试通过。开发8回合存于`results/execution_safety_probe1`：正常延迟0.4秒下原参照接触，队列预测没有接触但外扩分离量−5.05mm，两个本地保护组无接触、最小外扩分离量+5.96mm，但均无路终止。1秒无输出下原参照与仅队列预测都接触；两个本地保护组过期停车，余量+195.98mm，未到达。保持参数原样进入正式批次。

固定同输入反事实：上一轮窄路普通箱体种子8延迟0.4秒，第53帧（5.3s）是第一个旧预测放行而队列预测拒绝的帧；旧分离量+57.75mm，完整队列候选−14.20mm，即使此刻请求停车也为−2.99mm。只能说明旧预测漏算动作，以及晚发现时仅远端制动未必能保住余量，不把它当闭环成功。结果存于`docs/benchmarks/execution-counterfactual-v5.json`。冻结后不改两个新算法模块及上一轮全部算法源文件。
