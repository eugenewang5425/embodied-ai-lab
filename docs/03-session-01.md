# 第一次实验：随机动作为什么控制不了倒立摆？

实验日期：2026-08-09

2026-09-02 校正：本页“水平力”的口语描述指控制输入 `u`；原模型有 `gear=100`，实际执行器水平力为 `100u N`。关节角不完全等于物理倾角，零点偏置约 `0.001667 rad`，详见第三课。历史结果文件未覆盖。

## 我们刚刚做了什么

我们创建了一个 MuJoCo 倒立摆，并让程序连续执行 300 个仿真步。程序没有使用控制规律，而是在每一步随机选择向左或向右的作用力。

这个实验不是为了成功保持平衡，而是建立一个**随机动作基线**：以后加入控制器后，必须用数据证明它比随机乱推更好。

## 状态 observation

环境每一步返回 4 个数：

```text
[小车位置, 摆杆角度, 小车速度, 摆杆角速度]
```

可以把它与 GIS 中的要素状态类比：仅知道一个点的位置还不够预测它下一刻的位置，还需要知道运动速度；对倒立摆来说，还要知道摆杆的角度和角速度。

## 动作 action

动作只有 1 个数：

```text
[施加给小车的水平力]
```

正负号表示两个相反方向，绝对值表示作用力大小。随机策略不知道摆杆向哪边倒，因此它施加的力通常不能抵消倾倒趋势。

## 一次仿真循环

```text
读取状态 → 随机生成动作 → MuJoCo 推进物理时间
   ↑                              ↓
   └──── 返回新状态、奖励和终止信号 ────┘
```

这就是具身智能最基本的“观察—行动—环境反馈”闭环。后续改变的主要是中间的决策方法：从随机动作变成 PD/PID、LQR 或学习策略。

## 本次结果

| 指标 | 结果 | 含义 |
| --- | ---: | --- |
| 总仿真步数 | 300 | 固定实验长度 |
| 回合数 | 59 | 摆杆失败后重置了很多次 |
| 平均每回合长度 | 约 5.08 步 | 随机控制很快失败 |
| 最长回合 | 16 步 | 偶然维持的最好结果仍然很短 |
| 平均每步奖励 | 0.8033 | 约 80.3% 的步仍处于允许角度范围 |
| 最大绝对摆角 | 0.3598 rad，约 20.61° | 已明显偏离竖直方向 |

## 现在应该理解的三个结论

1. **状态不是画面本身**：它是控制器用于决策的一组数。
2. **动作不是目标**：动作是当前时间步施加给系统的控制量。
3. **控制需要反馈**：好的动作必须根据当前角度和角速度计算，不能与状态无关。

## 理论对应（Embodied-AI-Guide）

在 [Embodied-AI-Guide](https://github.com/TianxingChen/Embodied-AI-Guide) 的章节体系里，本课属于 Infrastructure 篇 Simulators 的地基：reset/step 接口、observation 与 action 的维度约定、terminated 与 truncated 的区别，是几乎所有具身智能实验共享的最小抽象。同一个接口也是 Algorithm 篇 Robot Learning（强化学习）问题的标准表述：状态、动作、奖励、终止条件一样不缺，而本课的“随机动作”就是完全没有学习的策略。

本课的数字给这个抽象标了量级：300 步里失败 59 个回合、平均每回合约 5.08 步、最长 16 步、平均每步奖励 0.8033、最大摆角 0.3598 rad（约 20.61°）。它定义了“不学习的下限”。以后任何控制器——手工的 PD/LQR 或学习得到的策略——都要在同一协议下与这组数字比较，这与 Infrastructure 篇 Benchmarks“先有固定协议的基线，才有可比的进步”的做法一致。

还有一条容易被忽略的对应：本课状态 `[小车位置, 摆杆角度, 小车速度, 摆杆角速度]` 由仿真器直接给出，是理想读数。Hardware 篇 Sensors 的真实传感器不会这样配合——后面课程会看到读数误差如何通过反馈变成真实运动。现在先记住：状态是控制器决策用的数组，不等于机器人真实知道的状态。

## 思考题

1. 平均每步奖励 0.8033，但平均每回合只有约 5.08 步、最长 16 步。为什么“八成的步没失败”与“很快失败”可以同时成立？这两个指标里哪个更接近“控制效果”？
   提示：把 300 步、59 个回合与失败重置机制放在一起算一算。
2. 最大绝对摆角 0.3598 rad（约 20.61°）已超过后续课程 0.2 rad 的失败线。随机动作偶尔也能撑十几步，靠的是什么？这提示对比实验必须固定哪些条件？
   提示：结合“最长回合 16 步”与“随机策略不知道摆杆向哪边倒”；等做完第二次实验，再用它的 20 个种子协议回看本课结果表。
3. 如果把随机动作改成“每步在正负最大力之间交替”，你预测平均回合长度会明显变长吗？先写下预测依据，再设计一个与本次协议可比的验证实验。
   提示：本课“一次仿真循环”的接口；对比时要保持步数、奖励与终止条件不变。
4. 本课指标表里没有“控制输入幅值”这一列。为什么从第二次实验开始必须补上它？少了它，PD 的对比表会漏掉什么信息？
   提示：第二次实验对比表最后一行“均方根控制输入 u”及其下方的注意事项。

实现一个 PD 控制器：

```text
控制力 = 比例项 × 当前角度误差 + 微分项 × 当前角速度
```

- 比例项负责把倾斜的摆杆推回竖直方向；
- 微分项负责抑制摆杆转动过快，减少来回振荡；
- 用与本次完全相同的指标比较 PD 与随机策略。
