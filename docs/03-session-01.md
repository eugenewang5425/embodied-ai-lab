# 第一次实验：随机动作为什么控制不了倒立摆？

实验日期：2026-08-09

2026-09-02 校正：本页“水平力”的口语描述指控制输入 `u`；原模型有 `gear=100`，实际执行器水平力为 `100u N`。关节角不完全等于物理倾角，零点偏置约 `0.001667 rad`，详见第三课。历史结果文件未覆盖。

## 我们刚刚做了什么

我们创建了一个 MuJoCo 倒立摆，并让程序连续执行 300 个仿真步。程序没有使用控制规律，而是在每一步随机选择向左或向右的作用力。

这个实验不是为了成功保持平衡，而是建立一个**随机动作基线**：以后加入控制器后，必须用数据证明它比随机乱推更好。

## 状态 observation

环境每一步返回 4 个数：

```text
[小车位置, 摆杆角度, 小车速度, 摆杆角速度]
```

可以把它与 GIS 中的要素状态类比：仅知道一个点的位置还不够预测它下一刻的位置，还需要知道运动速度；对倒立摆来说，还要知道摆杆的角度和角速度。

## 动作 action

动作只有 1 个数：

```text
[施加给小车的水平力]
```

正负号表示两个相反方向，绝对值表示作用力大小。随机策略不知道摆杆向哪边倒，因此它施加的力通常不能抵消倾倒趋势。

## 一次仿真循环

```text
读取状态 → 随机生成动作 → MuJoCo 推进物理时间
   ↑                              ↓
   └──── 返回新状态、奖励和终止信号 ────┘
```

这就是具身智能最基本的“观察—行动—环境反馈”闭环。后续改变的主要是中间的决策方法：从随机动作变成 PD/PID、LQR 或学习策略。

## 本次结果

| 指标 | 结果 | 含义 |
| --- | ---: | --- |
| 总仿真步数 | 300 | 固定实验长度 |
| 回合数 | 59 | 摆杆失败后重置了很多次 |
| 平均每回合长度 | 约 5.08 步 | 随机控制很快失败 |
| 最长回合 | 16 步 | 偶然维持的最好结果仍然很短 |
| 平均每步奖励 | 0.8033 | 约 80.3% 的步仍处于允许角度范围 |
| 最大绝对摆角 | 0.3598 rad，约 20.61° | 已明显偏离竖直方向 |

## 现在应该理解的三个结论

1. **状态不是画面本身**：它是控制器用于决策的一组数。
2. **动作不是目标**：动作是当前时间步施加给系统的控制量。
3. **控制需要反馈**：好的动作必须根据当前角度和角速度计算，不能与状态无关。

实现一个 PD 控制器：

```text
控制力 = 比例项 × 当前角度误差 + 微分项 × 当前角速度
```

- 比例项负责把倾斜的摆杆推回竖直方向；
- 微分项负责抑制摆杆转动过快，减少来回振荡；
- 用与本次完全相同的指标比较 PD 与随机策略。
