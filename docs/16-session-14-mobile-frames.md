# 第十四课：小车转了，地图里的方向变了吗？

本课进入原路线的第三阶段：移动机器人。先不安装 ROS 2，不加 SLAM，也不继续扩展机械臂调参。用一个差速车的二维小实验，把“轮子的运动”和“地图坐标”接起来。

## 先联系你已经学过的内容

倒立摆、机械臂让我们理解了状态、动作、反馈，以及关节空间如何映射到末端空间。现在换一台有两个独立驱动轮的小车：每个轮子通常由一个电机驱动。本课抽象为左右两个轮速输入，**没有模拟电机内部控制、力矩、加速度或摩擦**。

这与 GIS 的直接联系不是地图画得多漂亮，而是：**同一个对象，换一个坐标系，数字就会不同，但物理位置没有改变。** 本课是米制局部平面上的旋转和平移，不涉及经纬度投影、地球曲率或基准面转换。

先用已有真值位姿验证几何关系；下一课再研究里程计怎样估计位姿、为什么会积累误差。坐标转换正确，不等于知道小车真正在哪里。

## 1. 状态、动作和方向先说清楚

| 对象 | 本课定义 |
| --- | --- |
| 状态 | `[x, y, θ]`，车体中心在世界中的位置（m）与朝向（rad） |
| 动作 | `[左轮角速度, 右轮角速度]`，单位 rad/s；正值统一表示让该轮向前滚动 |
| 世界 W | 固定在地面，X/Y 不随车旋转；初始车头朝世界 +X |
| 车体 B | 原点在两轮轴线中点；x 向车头，y 向车的左侧 |
| 传感器 S | 安装在车体前方 0.12 m、左侧 0.04 m，朝向相对车头左偏 30° |
| 角度 | 俯视时逆时针为正；底层保存连续、不折返的朝向，界面换算为度 |
| 几何与时钟 | 轮半径 0.05 m，左右轮间距 0.30 m；每步 0.04 s，每例 4 s |

传感器只是理想的二维地标坐标读数：始终能看到同一个地标，不模拟相机、激光扫描、量程、视场、遮挡或噪声。这里 S 的定义也不是相机 optical frame 的轴约定。

平面车体位姿需要三个配置量，但无侧滑约束下不能同时独立控制“前进、横移、转向”三种速度。我们只有两个轮速输入，瞬时车体横向速度为零。**配置维数、输入数、动力学状态数不是同一个概念。**

## 2. 两个轮子怎样决定前进与转向？

想象两个人分别推小车两边：一样快就直走，一边更快就转弯；等速反向则围绕两轮中点原地转。

记轮半径为 r、轮间距为 b、左右轮角速度为 ωL、ωR：

```text
车体前进速度 v = r(ωL + ωR) / 2
车体转向速度 ω = r(ωR - ωL) / b

世界坐标速度：dx/dt = v cosθ
              dy/dt = v sinθ
              dθ/dt = ω
```

这组差速运动学关系可对照作者教材的[差速车运动模型](https://www.roboticsbook.org/S52_diffdrive_actions.html)。注意轮子的角速度与车体的转向角速度不是同一个量。

每个 0.04 s 区间假设轮速恒定，程序用恒定速度圆弧的解析积分更新姿态，直行是角速度趋于零的连续极限。不是将车直接移动到预先算好的终点；每例有 100 个运动区间、101 帧姿态。独立的整段直线/圆弧公式用来核验终点。

固定案例实跑结果：

| 案例 | 轮速 `[左, 右]` rad/s | 4 s 终点 `[x, y]` m | 终点朝向 |
| --- | --- | --- | --- |
| 直行 | `[4, 4]` | `[0.800, 0.000]` | 0° |
| 原地左转 | `[-2, 2]` | `[0.000, 0.000]` | 152.79° |
| 向左弯 | `[2, 4]` | `[0.437, 0.344]` | 76.39° |
| 向右弯 | `[4, 2]` | `[0.437, -0.344]` | -76.39° |
| 先左转 90° 再走 | 前 2 s 约 `[-2.356, 2.356]`；后 2 s `[4, 4]` | `[0.000, 0.400]` | 90° |

最后一例是重点：第二段仍在沿车体 +x 前进，只是车体 +x 已经朝向世界 +Y。小车没有横着滑过去。

轮速在 2 s 处可以瞬时切换，是运动学模型的理想假设；真实电机有加速过程，本课不据此讨论耗电或动力学可执行性。本课按预设时间表运动，**不是到点反馈控制，也没有目标到达成功率**。

## 3. 同一个地标为什么出现三套数字？

固定地标位于世界 `(1.1, 0.8) m`。对某个子坐标系中的点，先旋转到父系方向，再加上子系原点在父系中的位置：

```text
p_parent = t_parent_child + R(yaw_parent_child) · p_child
R(α) = [[cosα, -sinα], [sinα, cosα]]

传感器 → 车体：p_B = t_BS + R_BS · p_S
车体   → 世界：p_W = t_WB + R_WB · p_B
```

反过来，从父系变到子系，先减去平移，再乘旋转矩阵的转置。变换顺序不能交换；“世界→车体→传感器”描述的是坐标系层级，测量映射回地图则沿反方向逐级换算。

先转再走的终点，小车位于 `(0, 0.4)`、朝向 90°：

| 表达在哪个坐标系 | 同一地标的坐标 / m |
| --- | --- |
| 世界 W | `(1.100, 0.800)` |
| 车体 B | `(0.400, -1.100)` |
| 传感器 S | 约 `(-0.328, -1.127)` |
| S→B→W 完整转换 | `(1.100, 0.800)` |

车体读数的 y 为负，表示地标在车的右侧，不代表地标跑到地图下方。传感器有自己的安装偏转，所以 S 与 B 也不相同。

## 4. 故意做错一次，才能看清变换的作用

演示里的“错误坐标变换”只做 `p_wrong = 车体世界位置 + 传感器读数`，故意遗漏车体旋转、传感器旋转和安装偏移。它不是另一种合格的定位方法，只是常见坐标混用错误的反例。

五个案例完整转换的最大往返误差均小于 `1e-14 m`（实跑最大约 `6.28e-16 m`），属于浮点数一致性。先转再走例的错误转换最大偏差约 **2.386 m**，终点偏差约 **2.091 m**，红色假地标会随车乱跑。

这不是传感器精度、里程计精度或 SLAM 精度：读数由已知位姿生成，又用同一真值位姿变回去。要研究定位，下一课必须把真实位姿与估计位姿分开。

## 慢放：先做这个三分钟观察

在 `D:\项目\具身人工智能` 打开 PowerShell：

```powershell
uv run python -m embodied_learning.mobile_demo --results results/mobile_frames_2026-09-03
```

默认暂停、0.25×，选中“先左转 90°，再向前走”。支持播放/暂停、0.04 s 单步、回到起点、拖动时间轴和 0.1/0.25/0.5/1× 速度。4 s 记录在 0.25× 下约用 16 s 播放，不改变仿真步长。关闭窗口或按 Esc 退出。

1. 先看灰色世界轴保持不动，蓝色车体轴和紫色传感器轴随车转；箭头仅标坐标方向，不是实际杆件或传感器量程。
2. 在 2 s 附近暂停：朝向到 90°，下一步左右轮速变为相等。单步后世界 y 增加、世界 x 基本不变。
3. 勾选“显示错误坐标变换”：绿色地标保持固定，红色假地标移动。右侧观察同一个点的三套坐标和变回世界后的结果。
4. 换成“右轮更快：向左弯”，确认不是向右转。蓝/橙曲线是同一地标的传感器 x/y 坐标，不是两台车。

窗口只读保存的轨迹；终帧明确显示“没有下一步轮速”，不虚构末帧动作。曲线展示完整记录，竖线标记当前播放时刻；顶部平面图只画已经走过的轨迹。坐标轴初始可能重合，标签使用不同箭头长度和位置区分。

## 学完这一课，你应该能说清楚

1. 为什么右轮更快会向左弯？两个轮速能不能直接让车横移？
2. 车体前方与地图 +X 什么时候一致，什么时候不同？
3. 地标在传感器坐标中的 y 变负，为什么不能直接说它在地图的负 Y 区？

下一步仅增加一个新的问题：**编码器里程计与真实位姿分开后，小误差怎样随运动积累？** 先做无误差基线，再加入单一可控偏差进行配对实验；等这个差异解释清楚，再考虑状态估计、到点闭环和 ROS 2 的节点组织。不同时叠加随机噪声、打滑、SLAM 和新仿真器。
