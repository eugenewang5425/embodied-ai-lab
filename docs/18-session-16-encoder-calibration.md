# 第十六课：先校准尺子，再用其他路线验收

本课承接第十五课：车的真实运动没有改变，右轮编码器却多报转角，导致位置、朝向和地标落图一起偏离。现在只解决这个**固定比例错误**，不增加自由度、滤波器或大型框架。

## 1. 先用 GIS 的经验理解

可以把右轮编码器理解为一把刻度不准的尺子。坐标转换公式再正确，也不能让错误的尺度自动变准确。类似空间测量中用独立基准校准尺度：先有测量依据，再计算修正关系，最后用其他数据检查。

这里不是经纬度投影，也不是整张地图的配准。只估计**一个正数 c**，把右轮报告的转动增量乘以它，再送进原来的里程计。

要区分三件事：

- **原始编码器读数**没有因为标定而变准；它仍然多报。
- **送入里程计的读数**经过修正，因此估计位姿更接近真值。
- **真实车的运动和电机指令**完全没变；这不是控制器把车纠正回来，也不是在线定位纠偏。

## 2. 标定数据怎么来：不把答案直接填进去

另做四段直线运动，正向三段、反向一段。每段收集右轮累计转角增量，以及独立测距基准给出的带符号距离。

| 独立标定段 | 测距基准 / m | 右轮报告转角 / rad | 按已知半径 0.05 m 换算的原始距离 / m |
| --- | ---: | ---: | ---: |
| 前进 0.4 m | 0.400 | 8.160 | 0.408 |
| 前进 0.8 m | 0.800 | 16.320 | 0.816 |
| 前进 1.2 m | 1.200 | 24.480 | 1.224 |
| 后退 0.6 m | -0.600 | -12.240 | -0.612 |

当前“独立测距”是**仿真生成的理想外部测量**，不是已经用尺子、相机或真实机器人采到的数据。模拟器知道真实偏差，以便制造传感器读数；拟合函数只接收上表的转角、距离与已知半径，接收不到真实偏差或评估路线的真值。

四段是新生成的标定记录，不从待评估路线截取。上一课的直行 12 秒、方形 24 秒作为冻结的验证数据，只在系数确定之后使用；不能根据其终点误差反复调 c。

## 3. 一个比例系数为什么够用

一段直行可以先手算：

```text
原始轮程 = 半径 × 报告转角 = 0.05 × 8.16 = 0.408 m
修正系数 c = 独立测距 / 原始轮程 = 0.400 / 0.408 ≈ 0.980392
修正后的轮程 = c × 原始轮程
```

多段数据一起使用时，令 `x_i = r × 报告转角_i`、`d_i = 独立测距_i`，求使 `Σ(c x_i − d_i)²` 最小的 c，即过原点的一元最小二乘：

```text
c = Σ(x_i d_i) / Σ(x_i²)
```

只拟合比例，不再拟合截距，因为输入是每段的**增量**；编码器绝对零点在差分时已经消掉。程序保留起始计数，仅修正右轮增量，左轮不变。反向增量也必须保持负号。

实跑得到 `c = 0.9803921568627453`。检查用的理论值是 `1/1.02`，但代码不是把这个理论值直接交给估计器。例如一小步原始读数 `0.1632 rad`，经过标定送入里程计变为 `0.1600 rad`。

为什么不是简单乘 `0.98`？因为“多报 2%”意味着原读数为真实值的 `1.02` 倍；要反过来还原，应除以 `1.02`。两个百分比的参照量不同。

## 4. 三组同条件验证

真实车、轮速、原始编码器读数、时间步长与传感器观测全部共享，只改变读数预处理：

- 紫色“不修正（旧 +2%）”：`c=1`。
- 绿色“用准确尺子标定”：使用上述四段数据拟合的 c。
- 橙色“标定尺子偏大1%”：编码器数据不变，只把**标定用的独立距离**统一乘以 1.01，再重新拟合。

这是新版界面的名称；旧结果文件和静态图中的“未标定 / 独立标定 / 测距偏大1%”保持原样，以免改写历史记录。

正式记录：`results/encoder_calibration_2026-09-03_v2/`。

| 未参与标定的路线 | 未标定终点位置误差 | 理想基准标定后 | 标定测距偏大 1% 后 |
| --- | ---: | ---: | ---: |
| 直行 2.4 m / 12 s | 19.40 cm | <1e-10 m，仅数值舍入 | 9.69 cm |
| 方形一圈 / 24 s | 15.24 cm | <1e-10 m，仅数值舍入 | 7.72 cm |

理想标定后最大位置误差也小于 `1e-10 m`，不是只在终点碰巧抵消。图中绿色轨迹会被重合的蓝色真值遮住；误差曲线仍显示绿色接近零。

橙色组拟合出的 `c≈0.990196`，右轮残余有效比例为 `1.02×c≈1.01`，因此结果与第十五课的 +1% 组在数值容差内一致。这不是新的随机噪声：**基准本身偏大，偏差也会被带进标定。多测几次同样偏大的距离，不能自动消除它。**

报告保留终点、最大、RMS 位置误差、朝向误差和地标落图误差。与上一课相同，方形的位置误差可能暂时下降，不代表发生在线纠偏。

## 5. 三步教学：先看测量，再算系数，最后验证

在项目根目录的 PowerShell 中运行：

```powershell
uv run python -m embodied_learning.calibration_demo
```

新版窗口标题是“第十六课 · 看测量 → 求系数 → 换路线验证”，默认进入**① 对照测量**，不再直接打开三条轨迹。若仍看到只有轨迹的旧窗口，那是旧进程；上述命令会启动新版，不必重新生成实验数据。

1. **① 对照测量**：四行表格来自既有 `calibration.json`。先看第1段：尺子 `0.4000 m`、编码器换算 `0.4080 m`，相差 `8.00 mm`。点其他行可查看前进与后退数据；负数表示后退。
2. **② 求修正系数**：点“用这四段数据计算 c”，才显示第1段手算 `0.4000÷0.4080` 和四段最小二乘的实际分子、分母，得到 `0.980392157`。计算前验证页不可进入。这里调用原拟合函数，输入就是前一页显示的测量，不用验证路线的终点误差调参。
3. **③ 换路线验证**：点“带着这个系数，换路线验证”，进入默认暂停、0.25× 的原回放。单步看 `0.1632→0.1600 rad`。时间轴到 12 s，同一时刻切换三种方法，看 19.40 / 近零 / 9.69 cm。
4. 返回①，选“标定用的尺子偏大 1%”：编码器列不变，参考距离从 `0.4000` 变为 `0.4040 m`；旧系数清空、验证页重新锁定。重新计算得到 `0.990196078`，再验证为何仍残留误差。返回测量/计算页会暂停隐藏的回放，保留验证时刻以便对照。
5. 验证页可切方形路线，回起点暂停；“下一段”观察直行与原地转弯。三组曲线保持同轴，不新增自由度或仿真框架。

### 为什么还是上一课那些轨迹？现在直接说明对应关系

验证页顶部固定显示：**不修正 = 旧 +2%；准确尺子标定 ≈ 旧 0%；尺子偏大1%标定 ≈ 旧 +1%**。未修正轨迹完全复用旧 +2%，其余只差浮点舍入；这不是三种新运动能力。本课新增的是“从独立测量求出系数”的过程，复用旧路线是为了做同条件验证。

### 灯杆落图改成可选辅助

默认隐藏地标标记、落图数值及其指标选项。勾选“辅助：把灯杆放到地图”才显示“真实灯杆”和“地图上的灯杆”，并解释：灯杆不动，自身定位误差可能把它放错地方；这里只展示误差，不参与定位或控制。关掉辅助时自动退出落图指标，保留位置/朝向曲线。

这不是“标定位置”，也不是机器人要追赶的目标点。显示或隐藏灯杆均不改变任何运动、编码器或位姿数据。

完整直行在 0.25× 下约 48 s，方形约 96 s；回放速度不改变仿真步长。按 Esc 或关闭窗口退出。

## 6. 本课不能说明什么

- 近零误差只说明理想固定比例模型可以被一个比例因子抵消，**不是硬件定位精度或泛化成功率**。
- 假设已知初始位姿、精确轮半径与轮距、左轮无偏差、无打滑。编码器不能自己找到世界坐标原点。
- 单靠这些直线数据，不能区分“右轮半径不准”和“右编码器比例不准”，只能识别二者对轮程的合成尺度；也不能标定轮距。
- 实车标定要独立确认直行与测距可靠性。打滑、转弯或弯曲路径不能随便拿终点直线距离当轮子走过的长度。
- 固定 c 不会处理随时间变化的噪声、滑动或延迟；本课也没有利用地标纠偏、滤波、闭环控制或 SLAM。

### 上轮 Tk 问题的处理边界

排查时旧错误在第十二课和第十五课之间转移，均在 `Tk()` 创建阶段，报错中的库文件实际存在。显式回收循环引用的方案一轮通过、下一轮仍失败，因此撤掉；没有证明 GC 就是根因，也没有通过改系统环境变量或重装来试错。

当前将 6 项真实 Tk 集成测试标为 `isolated_tk`，每项在独立 Python 子进程中执行原测试，匹配每个演示独立启动的使用方式。每个子进程限时 120 s，失败原样导致父测试失败，不跳过、不重试。额外单测确认失败传播和防递归。这是**进程隔离的工程解决方案，不是声称已经修复 Tcl 内部缺陷**；其精确底层原因仍未确定。

隔离后、添加第十六课前，282 项全量连续通过两次（37.87 s、37.86 s）；添加后见上述 313 项结果。Python 官方文档也提醒，同线程中的多个 Tk 解释器共享事件队列，需要谨慎管理，但该一般说明不能证明本次异常的具体原因：[Tkinter threading model](https://docs.python.org/3/library/tkinter.html#threading-model)。第十二课历史桌面验收限制仍保留，不能被本次单测结果覆盖。

## 理论对应（Embodied-AI-Guide）

在 [Embodied-AI-Guide](https://github.com/TianxingChen/Embodied-AI-Guide) 的地图里，本课对应（6）Control 篇·机器人学导论（6.3.3 里程计与 SLAM）中"里程计标定"的前置内容：系统误差只要能被参数化，就可以用独立观测把它估计出来。本课是这个思想的最小实例——一个参数 c、四段观测、过原点一元最小二乘的闭式解 `c = Σ(xᵢdᵢ)/Σ(xᵢ²)`。指南里更复杂的标定与估计方法，本质上都在重复"参数化 → 独立观测 → 最小化残差 → 冻结验证"这套流程，只是参数和观测更多。

数字上的闭环很干净：第一段标定数据给出 0.408 m 对 0.400 m（差 8.00 mm），四段拟合出 c≈0.980392；两条冻结验证路线的终点误差从未标定的 19.40/15.24 cm 降到理想标定后的 <1e-10 m。参数估计在"模型恰好包含真实误差"时可以完全消除该误差——这是确定性参数可辨识的最理想情形，也因此要立刻补上下一条警告。

橙色组是本课最重要的理论警告：标定用的独立距离统一偏大 1%，拟合出 c≈0.990196，验证残留 9.69/7.72 cm——数值上正是第十五课 +1% 组的结果。**基准有偏，估计就有偏；重复同一把偏大的尺子，无论多少次，都不能把这 1% 平均掉。**这在估计理论里就是"观测模型的系统偏差不会被冗余观测消除"，也是真实标定流程要求基准可溯源、宁可保留不确定度声明也不虚报精度的原因。

本课还提前演示了两条属于估计与学习方法的纪律：其一，四段标定数据与验证路线严格分离，"不能拿验证路线的终点误差反复调 c"与（4）Algorithm 篇·Robot Learning 的 train/test 分离是同一条规则；其二，直线段只能识别"半径 × 编码器比例"的合成尺度，无法区分二者，也不能标定轮距——这是参数可辨识性问题，6.3.3 的标定文献会用转弯等更丰富的激励来处理。本课没有走向这些扩展：一个参数、能被一个正数解释的误差，就先用最简工具解决。

## 思考题

1. 为什么修正系数是 c≈0.980392 = 1/1.02，而不是 0.98？"多报 2%"和"乘 0.98"各自的参照量是什么？
   提示：第 3 节"为什么不是简单乘 0.98"；用一小步原始读数 0.1632 rad 分别走两种算法比较。
2. 橙色组（标定尺子偏大 1%）标定后直行终点仍差 9.69 cm，恰好与第十五课 +1% 组一致。多做几遍最小二乘能把这 1% 平均掉吗？为什么？
   提示：第 4 节末段——"基准本身偏大，偏差也会被带进标定。多测几次同样偏大的距离，不能自动消除它。"
3. 如果允许拿直行验证路线的终点误差反复微调 c，总能把这条路线"调准"。为什么本课禁止这样做？这条规则在指南的哪个学习主题里同样成立？
   提示：第 2 节"四段是新生成的标定记录，不从待评估路线截取"与验证数据冻结的说明。
4. 四段直线数据为什么区分不了"右轮半径不准"和"右编码器比例不准"？要区分二者，需要增加什么样的标定数据？
   提示：第 6 节"本课不能说明什么"第 3 条；想一想两者对"单位转角对应的轮程"各有什么影响。
5. 标定改变的只是"送入里程计的读数"，原始编码器读数仍多报。为什么要强调这个区分？如果把 c 直接写进编码器驱动里，将来更换轮子或编码器后会发生什么？
   提示：第 1 节"要区分三件事"；思考 c 的适用范围取决于哪些前提。

## 本课停止点与下一步

先回答三问：

1. 这次标定究竟改变了原始读数、估计结果，还是电机运动？
2. 为什么不能拿同一条验证路线的终点误差反复调 c，再宣称验证成功？
3. 基准距离都偏大 1%，多做几遍最小二乘能自动消掉这 1% 吗？

下一步只增加一种变化：**在固定比例已标定后，引入有种子的逐区间测量噪声，分开看平均误差与分散程度**。先确认固定标定解决不了哪部分问题，再决定是否需要外部定位信息或滤波；不同时加入打滑、动力学、ROS 2 与 SLAM。
