# 第十课：换一批路径，它还可靠吗？

本课不增加电机、自由度、噪声或新算法。继续使用两个关节电机，单个电机最大 ±0.25 N·m。只把第九课的一条路径扩展成可复现的多路径测试，学习分清“任务不可行”“参考算法卡住”“执行误差”和“验收未达标”。

## 先记住这个反例

**有两个电机、有足够力矩，不代表参考算法一定会给出正确动作。**

机械臂沿 X 轴完全伸直，末端在 `(0.70,0) m`，要求沿直线收到 `(0.50,0) m`。整条线都在可达区域内；但当前局部 Jacobian 算法生成的两个关节参考角始终为零，PD 算出的两个力矩也始终为零，机械臂原地不动。

同一台机械臂换成解析 IK 终点 + 原关节 PD，可以到达这个点。因此这不是“机械臂本身到不了”，也不是“电机推不动”。限制在当前局部参考生成方法。

## 1. 先看失败慢放

在 `D:\项目\具身人工智能` 运行：

```powershell
uv run python -m embodied_learning.arm_path_demo --results results/arm_path_batch_2026-09-02_v2/trials/singular_inward
```

默认暂停、0.25×。播放时先选 Jacobian，观察三个量：

1. 橙圆（按时间规定的位置）向左移动，实际机械臂却不动。
2. 两个下一步力矩始终为零。不是电机输出到上限仍推不动。
3. 偏离线段始终为 0，但最后距离终点仍有 200 mm；“仍在线上”不等于完成了路径。

随后切换“关节角平滑插值”：机械臂会收回来，但走的并非严格直线。其最大偏离约 7.670 mm，仍未通过 2 mm 路径要求，不过末端到达和停稳通过。

窗口右侧新增“整段结果”和“停稳未过”说明，区分完整记录的验收结果与当前帧的瞬时误差。图中实线表示已经播放，虚线预览完整记录；切换方案会回到起点并暂停。

## 2. 一次成功不能代表各种路径都成功

本批固定 seed=400，事先生成清单，再运行控制器。三种方法始终共享同一路径的初态、终点、动力学参数与力矩限制。

| 测试集合 | 数量 | 变化了什么 | 没变什么 |
| --- | ---: | --- | --- |
| 内部路径 | 12 条 | 初始姿态、终点、方向、长度 | 两个电机、正肘角分支、控制器与参数 |
| 接近伸直 | 12 条 | 终点半径接近 0.70 m | 同样 8 s 移动 + 3 s 停留 |
| 固定反例 | 1 条 | 从完全伸直向内收 | 同一模型与三种方法 |

共 24 条随机路径、1 条固定反例，每条跑三种方法，共 75 个动力学回合。固定反例与随机统计分开，不混成“25 次随机测试”。

抽样规则：

- 内部组：初态与目标的 q1 分别均匀抽取于 [-90°,90°]，q2 于 [40°,140°]，线段到原点的最小距离至少 0.18 m。
- 近伸直组：初始末端半径 0.40–0.58 m，方向 [-60°,60°]；终点半径 0.6995–0.69999 m，终点方向在初始方向基础上偏转 [-35°,35°]。
- 两组均要求整条线几何可达、长度 0.12–0.65 m、初始速度为零。每组使用独立的 `SeedSequence([seed, group_index])`，改变每组数量不会改变另一组的随机序列前缀。
- 本次共有 6 个候选按预先规定的几何/长度条件剔除，原因和候选参数都记录在 manifest.json。没有根据控制结果挑选“好看的成功案例”。

这不是均匀覆盖整个工作空间的小样本，更不是任意任务的成功概率估计。

## 3. 结果：先区分到达和路径验收

仍沿用第九课的标准，没有为这批结果放宽门限：

- 末端停稳：记录结束前连续至少 0.5 s，且在运动期结束后，末端误差 ≤2 mm、每个关节误差 ≤0.01 rad、速度 ≤0.02 rad/s。
- 路径通过：完整运行 11 s，满足末端停稳，同时 0–8 s 最大偏离有限线段 ≤2 mm。

| 方法 | 内部组停稳 | 内部组路径 | 近伸直组停稳 | 近伸直组路径 |
| --- | ---: | ---: | ---: | ---: |
| 只给终点的 PD | 12/12 | 0/12 | 12/12 | 0/12 |
| 关节角平滑插值 | 12/12 | 1/12 | 12/12 | 0/12 |
| Jacobian 路径 | 12/12 | 12/12 | 8/12 | 8/12 |

只给终点组本来没有按直线或按时刻移动的目标；不能因为它路径验收未通过，就笼统称原 PD 无效。关节插值偶尔也能满足 2 mm 门限，不代表它保证末端直线。

Jacobian 内部组的最大偏离范围约 0.060–0.520 mm；近伸直组约 0.305–1.470 mm。所有 75 个回合都完整完成，没有触发物理速度/数值失败。所有随机 Jacobian 回合均没有电机力矩饱和、没有参考速度限幅。

### 近伸直组的四个“未通过”，到底差在哪里？

四个案例均满足末端位置和速度要求，路径偏离也小于 2 mm；问题是最后 0.5 s 中，肘关节角误差尚未持续低于 0.01 rad。

| 案例 | 最后一帧肘角误差 | 最后 0.5 s 最大肘角误差 | 最后一帧末端误差 |
| --- | ---: | ---: | ---: |
| near_extension_01 | 0.00817 rad | 0.01030 rad | 0.061 mm |
| near_extension_02 | 0.01125 rad | 0.01351 rad | 0.072 mm |
| near_extension_03 | 0.00880 rad | 0.01089 rad | 0.062 mm |
| near_extension_10 | 0.01374 rad | 0.01619 rad | 0.081 mm |

注意 01 和 03：最后一帧已经达标，但持续时间不足。这正是不能只截取最后一帧说成功的原因。这里的失败也不等于“机械臂严重跑偏”。

接近伸直时，某些关节变化只能带来很小的末端位移，末端误差很小仍可能留下可观的关节角误差。阻尼最小二乘又抑制了这些难运动方向上的参考速度。当前证据没有显示力矩不足；但不通过仅靠相关性就宣称某个参数是唯一原因，也不据此立刻调大增益。

如果后续真实任务只在意末端、不要求特定关节姿态，可以重新讨论验收标准；那属于任务定义变更，不能在看到未通过以后悄悄修改本批标准。

查看 01 案例：

```powershell
uv run python -m embodied_learning.arm_path_demo --results results/arm_path_batch_2026-09-02_v2/trials/near_extension_01
```

## 4. 怎样区分问题出在哪一层？

不用先引入新控制器，先沿已有的数据链检查：

```text
规定的末端路径 pd
    ↓ 参考生成
关节参考 qr，以及它对应的末端 f(qr)
    ↓ PD 根据实际角度和速度算力矩
请求力矩 → 电机限幅后的实际力矩
    ↓ MuJoCo 动力学
实际末端 p
```

报告现在分别记录：

- 参考误差：`f(qr)-pd`，参考生成器有没有给出所需路径？
- 执行误差：`p-f(qr)`，实际机械臂有没有跟上参考？
- 请求力矩与实际力矩：是否碰到 ±0.25 N·m？请求值不是电机真实施加值。
- 最小奇异值与参考限速：是否接近缺失运动方向，参考速度是否被缩放？
- 最后 0.5 s 的位置、关节角、速度门限：是否真的满足停稳？

前两个是向量误差，它们的 RMS 数值不能直接相加。力矩饱和也只是一个现象，不是自动判定失败的规则：本批只给终点组每回合都曾饱和，却全部到达并停稳。

固定反例的数据非常明确：参考误差 RMS=125.227 mm，执行误差 RMS=0，两电机请求/实际力矩全为 0。这里可以定位为“参考没动”，而非“电机跟不上”。这个结论只针对当前算法在该初态上的行为。

在完全伸直的一瞬间，局部 J 的径向速度为零；不意味着有限运动后永远无法向内收。下一步可以研究逐点解析 IK、离开奇异位形的起步策略，或者调整路径，但本课先保留失败，不偷偷加入脱困动作。

## 5. 哪些路径连控制器都不该运行？

三个固定几何检查都在仿真前拒绝：

1. 终点半径 0.75 m，超过两根杆总长 0.70 m。
2. 终点在原点，落在半径 0.10 m 的不可达内孔中。
3. 从 `(0.35,0)` 到 `(-0.35,0)`：两个端点可达，但直线经过不可达内孔。

这些不是三个“控制器失败回合”，不计入控制成功率。特别要区分第三种与完全伸直向内收：后者整条路径几何可达，只是当前参考生成方法卡住。

输出必须是新目录。正式记录在 `results/arm_path_batch_2026-09-02_v2/`：

- trials/各案例/summary.json 与 trajectories.npz：实际状态、力矩、参考、每个时间点的原始记录；直接供原慢放窗口读取，不复制出新 GUI。

自动测试共 153 项通过，包括固定种子复现、组间随机序列独立、整条路径几何检查、完整配对、零力矩卡住反例、最后一帧与持续门限区别、旧实验回归和输出禁止覆盖。

第一次结果目录 `results/arm_path_batch_2026-09-02/` 保留。其清单哈希按内存中的 LF 文本计算，而 Windows 写文件时转成 CRLF，导致报告哈希与文件字节不符；这是记录问题，不是动力学失败。修复为固定换行并对实际文件字节计算哈希后，新目录完整复跑，学习结论不变。请使用 `_v2`。

本轮用 computer-use 实际核验失败回放：仿真 t=6.08 s 时，实际末端仍在 70 cm，规定点约 51.87 cm，时间跟踪误差 181.350 mm；两个下一步力矩均为 0，窗口显示“整段结果：未通过 / 停稳未过：末端位置、关节角”。播放中的三色曲线与侧栏布局可读。观察到回放速度已被手动调整后停止切换控件，不接管后续播放；末尾 0.5 s 条件另由自动测试和原始数组核验。

## 本课结束时只需要理解三件事

1. “两个电机正常工作”和“任务完成”之间还隔着参考生成、控制与验收。
2. 未通过可能是持续时间或关节姿态未达标，不一定是画面上明显偏离。
3. 增加随机性要先固定抽样规则、保留失败，再讨论改进；不是反复换种子直到全绿。

下一小步可以对照“局部 Jacobian”与“逐点解析 IK”在奇异初态上的表现，保持 2R、同一电机和同一条路径。先解决已出现的具体限制，再考虑 3R 冗余、接触或噪声。
