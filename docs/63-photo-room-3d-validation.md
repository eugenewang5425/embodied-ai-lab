# 照片房间三维验证：从平面地图走向有高度的障碍物

本次建立了可编辑 Blender 模型、MuJoCo 场景和第一轮算法迁移试验。模型参考本地 40 张房间照片，属于**人工解释照片后搭建的参数化场景**。尚未完成摄影测量、相机位姿恢复或全屋尺寸标定。

已确认桌面高度为 0.69 m；用户提供的 0.65 m 宽度暂按桌面前后短边解释。房间暂设 3.40 × 3.80 × 2.70 m，床为 2.00 × 1.50 m，床底净空为 0.22 m，均为待校准假设。因此下面的结果是这个模型内的模拟证据，不能当成真实房间的定位精度或通过性保证。

## 1. 模型与可查看文件

生成目录为 `results/photo_room_v1/`。原始照片保留在 `建模照片临时文件夹/`，生成物和照片均由 Git 忽略。

| 文件 | 用途 |
| --- | --- |
| `layout.json` | 已知尺寸、估计尺寸、照片对应关系及假设；改尺寸的入口 |
| `geometry.json` | Blender 与 MuJoCo 共用的三维几何清单 |
| `scene.xml` | MuJoCo 场景，134 个几何体；房间、家具与机器人 |
| `photo_room.blend` | 可编辑的家具对象、材质、剖视集合和机器人回放关键帧 |
| `overview.png`、`interior.png` | 房间剖视与人眼高度的模型检查图 |
| `replay.gif` | MuJoCo 实际渲染的机器人回放及估计轨迹 |
| `validation_v3/summary.json` | 完整结果、门槛判定和校验值 |
| `validation_v3/trajectories.npz` | 真实位姿、编码器、偏差里程计、观测、地图和 PF 轨迹 |

Blender 默认隐藏靠观察者的两面墙，方便看室内结构；这些墙仍存在于 MuJoCo 碰撞与射线模型。Blender 中按空格可播放保存的运动关键帧。回放速度只用于展示，不代表真实车辆的运动时长。

## 2. 为什么这次需要三维几何

此前课程的障碍物主要是平面区域。真实房间里，桌面在地面上方，桌腿很细，椅子的轮脚比激光安装位置低，床架又可能高于激光而低于机器人顶部。

同一个位置，在不同高度可能有不同答案。例如模型中床架下沿高 22 cm，激光高 18 cm，它可以从床架下射过去；机器人本体高 32 cm、底部离地 2 cm，顶部达到 34 cm，就会碰到床架。单张水平激光切片没有包含这段竖直方向的信息。

| 变量 | 当前值 | 怎么影响实验 |
| --- | ---: | --- |
| 激光高度 `lidar_z` | 0.18 m | 决定水平射线会打中哪个表面 |
| 机器人半径 | 0.15 m | A* 地图需要向障碍物外膨胀，给机身留出空间 |
| 机器人竖向范围 | 0.02–0.34 m | 这段高度内任意障碍物都可能碰到机身 |
| 床底净空 | 0.22 m，估计 | 决定床下能否容纳整台机器人 |
| 栅格分辨率 | 0.04 m | 每格代表 4 cm；规划另加一格裕量 |
| 右轮编码器比例偏差 | +2% | 实际运动相同，估计里程计逐渐产生航向和位置偏差 |
| 射线数 / 最大量程 | 64 / 4 m | 从 MuJoCo 三维实体求交生成观测 |
| 测距噪声标准差 | 0.01 m | 三个传感器种子改变噪声和 PF 随机性 |
| PF 粒子数 | 200 | 四种地图输入采用相同粒子数与配对随机种子 |

## 3. 路径规划怎样验证

复用第 43 课的 A*、地图膨胀与路径简化代码。两种规划地图都来自场景真值几何，是用于检查表示方式的诊断对照，尚未由机器人探索生成。

- **低位激光切片图**：只投影 18 cm 高处的几何物体。
- **机身高度体积图**：投影 2–34 cm 高度内的几何物体，再按机器人半径膨胀。

得到路径后，沿路径生成差速车的原地旋转和直线运动，再逐位姿交给 MuJoCo 检查接触。这里的“接触帧”是穿入物体的采样位姿数，多帧连续接触不能当成多次独立撞击。

| 任务 | 低位切片规划 | MuJoCo 接触检查 | 机身体积规划 |
| --- | --- | --- | --- |
| 进入床下 | 产生路径 | 50 个采样位姿中 25 个与床架接触 | 拒绝，目标处没有足够高度 |
| 前往中央通道 | 产生路径 | 26 个位姿，0 接触 | 产生路径，0 接触 |
| 进入桌下 | 产生路径 | 48 个位姿中 18 个碰到办公椅轮脚 | 当前摆放下拒绝路径 |

本地 `validation_v3/height_planning.png` 并列展示两张地图与床下路径。右图拒绝规划意味着“在当前模型与裕量下无路”，不能写成机器人完成了到达任务。

追加的高度敏感性诊断固定路线任务，扫描床底净空 18、22、40 cm 与激光高度 12、18、30 cm，共 9 组。床底净空 40 cm 时，三种激光高度都能给出通过床下的路径，且 50 个采样位姿均无接触；净空 22 cm、激光 18 cm 时仍有 25 个接触位姿。结论依赖净空与机身高度的关系，实际净空需要测量。

## 4. 里程计、地图和定位怎样关联

参考路线围绕房间中央空地巡游。第一圈采集建图，随后两圈做定位比较。运动由已知参考路线规定，采用差速运动学积分；MuJoCo 提供三维观测与接触检查。没有执行轮胎摩擦、打滑动力学或“用估计位置控制车辆”的闭环导航。

第一圈里，同一批扫描分别使用真实位姿与有偏差的里程计落到栅格中。这样，两张端点地图的数据完全相同，区别只在“这些观测被放到了哪里”。定位阶段，所有组都获知同一个初始位姿，之后只使用有偏编码器增量和观测，PF 不读取真值重置。

复用第 15 课的编码器积分、第 56 课的扫描投影与粒子滤波实现。PF 的四张地图分别为：

1. **匹配激光高度的理想切片图**：表示“如果已知传感器实际能看见的几何”。
2. **机身高度投影图**：表示“把适合避障的图直接拿来匹配激光”，它可能包含激光看不见的床架或轮脚。
3. **同帧扫描真值落点图**：只保留实际观测到的端点，使用真值位姿投影，属于诊断上限。
4. **里程计自建图**：用有偏编码器估计位姿投影扫描，不用真值决定落点。

| 方法 | 三组种子的平均误差范围 | P95 误差范围 |
| --- | ---: | ---: |
| 纯里程计 | 0.187 m | 0.354 m |
| 匹配高度理想图 PF | 0.051–0.052 m | 0.082–0.085 m |
| 机身高度投影图 PF | 0.129–0.132 m | 0.183–0.199 m |
| 同帧真值落点图 PF | 0.018–0.025 m | 0.033–0.044 m |
| 里程计自建图 PF | 0.099–0.107 m | 0.146–0.166 m |

`validation_v3/trajectories.png` 中黑线是参考运动，红线是有偏里程计，青线和蓝线分别是匹配高度理想图、自建图的 PF 估计。三组种子的均值和 P95 见 `localization_metrics.png`。PF 轨迹是位置估计，不是机器人实际执行了另一条路线。

本轮四种 PF 都在三个传感器种子下改善了均值和 P95。匹配传感器高度的图比机身体积投影图更适合本次定位，说明**避障图与定位观测模型需要分别匹配各自用途**。同帧真值落点图更好，也说明扫描落点与地图表示都有影响，不能简单归因为“只要地图越完整，定位就越好”。

自建图相对真值落点图的精确率为 0.560、召回率为 0.786，中位偏移 0.08 m。本轮对齐容差为两个 4 cm 栅格，即 0.08 m；之前跨场景基准的容差为 0.30 m，两个结果不能直接按同一门槛比较。

## 5. 哪些结论仍然没有验证

本轮提供一个房间模型、三个噪声种子的局部证据。三个种子不是三个独立房间，不能替代原先 ISO/ANISO 多场景门槛；原跨场景基准的失败结论继续有效。

这些结果没有验证真实 RGB-D 回环识别、视觉 SLAM、相机标定误差、动态家具、玻璃反射、轮胎打滑、机器人自主探索或全局重定位。RGB 和深度图只是同一场景的传感器渲染检查。本轮的算法复验范围是 A* 的空间表示、编码器漂移与 PF 定位，不覆盖控制和学习课程的全部结论。

模型的床底、椅脚和通道是近似几何，不能由当前结果反推真实房间一定撞床或一定能通行。下一轮应补房间尺寸、桌长、床长宽和床底净空，先锁定几何，再调整局部摆放并做独立布局对照，最后把估计位姿接入闭环控制。

## 思考题

1. 激光从床下射过去，为什么机器人仍然可能撞床？需要知道哪两个高度才能判断？
2. 机身体积图适合避免碰撞，为什么拿它做本轮定位时误差反而更大？
3. 为什么必须使用同一批扫描比较真值落点图与自建图？换一圈扫描会混入哪些因素？
4. 自建图 PF 在这里改善了定位，能否推翻之前跨场景试跑的失败？还缺哪些独立证据？

## 复现与修改

```powershell
# 生成本地几何与 MuJoCo 文件；也可用 --layout 指向修改后的尺寸 JSON
uv run python -m embodied_learning.photo_room --output results/photo_room_v1

# 已完成的实验目录禁止覆盖；重跑请选择新目录
uv run python -m embodied_learning.experiments.photo_room_validation --layout results/photo_room_v1/layout.json --output results/photo_room_v1/validation_recheck

# Blender 模型与照片参考风格渲染；只在已安装 Blender 的本机使用此路径
& 'D:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --python-exit-code 1 --python scripts/build_photo_room_blender.py -- --input results/photo_room_v1 --validation validation_recheck
uv run python scripts/render_photo_room_replay.py --room results/photo_room_v1 --validation validation_recheck

# 打开 MuJoCo 可交互场景
uv run python -m embodied_learning.photo_room --layout results/photo_room_v1/layout.json --view
uv run python scripts/test.py quick tests/test_photo_room.py
```

文件依据：`photo_room.py` 负责几何与 MuJoCo 适配；`photo_room_validation.py` 负责配对试验；Blender 和 GIF 脚本负责可视化。7 项新增测试检查桌面实测尺寸、不同高度射线、机身接触、净空变化、A* 路径和编码器偏差。
